# 平台风险控制加固设计

## 目标

在不改变现有 API 成功响应、任务状态语义和 SQLite 兼容性的前提下，修复统一平台风控中已确认的旁路、误记成功、历史计数和数据生命周期问题，并补齐回归测试。

## 范围

本次包含以下修复：

1. 平台风险、认证和网络异常不得被嵌套读取循环吞掉或记录为成功。
2. 刷新账号资料、读取已发布作品、笔记媒体和笔记评论必须经过账号及网络出口闸门。
3. 删除账号时同步清理该账号的风险状态与风险事件，避免 SQLite 复用账号 ID 后继承旧状态。
4. 升级前已完成但 `done_at` 为空的发布任务，在历史兼容计数中使用 `created_at`。
5. `risk_control.mode` 只接受 `conservative` 和 `custom`；未知值在加载配置时回退为 `conservative`，避免拼写错误放宽保护线。
6. 无效账号时区回退到 `Asia/Shanghai`，保持现有默认账号语义。
7. 风险事件除了启动清理外，还由引擎按日执行保留期清理。
8. 删除本次修改后不再使用的旧风控辅助方法。

不包含平台业务接口重写、数据库迁移框架替换、API 路径调整或前端重构。

## 设计

### 1. 结构化读取结果

平台读取仍由 `MonitorEngine` 编排。嵌套循环遇到异常时按以下规则处理：

- `risk`、`auth`、`network`：立即终止当前逻辑读取，把原始异常或错误字符串传给 `RiskController.record_failure()`。
- `business`：保留现有可继续或失败语义，但不得伪造成功。
- 明确的空集合仍视为成功；异常导致的空集合必须携带错误。

小红书评论目标发现返回首个结构化错误，不再用无错误的空列表掩盖异常。笔记详情批量读取在首个受控风险异常后停止，外层读取结果为失败。

### 2. API 读取闸门

新增一个仅供 `app/main.py` 使用的轻量包装，复用 `MonitorEngine.guarded_read_pair()`：

- 账号资料和已发布作品列表使用 `READ_LIGHT`。
- 笔记媒体、笔记评论使用 `READ_HEAVY`。
- 闸门拒绝时维持 HTTP 200，并返回现有风格的 `skipped` 与 `reason` 字段。
- 平台错误继续映射为现有 HTTP 400，但同时持久化风险分类。
- 同一个逻辑操作中的回退请求留在同一账号锁和网络锁内。

### 3. 风险数据生命周期

删除账号的同一数据库事务中删除 `AccountRiskState` 和全部 `RiskEvent`。本次不依赖 SQLite 外键级联，因为现有数据库未统一启用外键约束，显式删除对存量数据库更可靠。

### 4. 历史发布计数

历史任务计数只用于兼容没有对应 `RiskEvent` 的存量记录：

- `PublishTask.status == "done"` 且 `done_at` 非空时使用 `done_at`。
- `done_at` 为空时使用 `created_at`。
- 最近成功时间同样采用上述有效完成时间。
- 继续采用现有事件数与任务数去重策略，避免扩大本次改动范围。

### 5. 配置和时区

- 加载 YAML 时规范化 `risk_control.mode` 的大小写和空白。
- 未知模式回退 `conservative`；`custom` 必须显式书写。
- 无效 `timezone_id` 使用 `Asia/Shanghai`；若运行环境连该时区数据也缺失，则使用固定 UTC+8。

### 6. 定期清理

`MonitorEngine` 保存上次风险事件清理日期。主循环每天最多调用一次 `prune_events()`；启动时的首次清理保留。清理失败只记录日志，不中断任务调度。

## 错误处理与兼容性

- 不改变已完成任务的 `done` 语义。
- 风控、认证和网络错误继续让写任务保持 `pending`。
- 读取闸门拒绝不更新平台对象的 `last_scan_at`。
- 删除账号接口仍保持幂等。
- 不修改现有风险表结构，因此无需新增数据库迁移。

## 测试

新增或扩展回归测试，覆盖：

1. 小红书嵌套评论读取遇到 429 时返回错误且不记录成功。
2. 受保护 API 在冷却期间不调用平台客户端。
3. 删除账号后风险状态和事件均不存在；复用 ID 的新账号不继承冷却。
4. `done_at=NULL` 的历史发布参与最小间隔、小时和每日额度。
5. 未知风险模式保持保守硬限制，显式 `custom` 仍可自定义。
6. 无效时区按 UTC+8 计算本地日界线。
7. 引擎定期清理每天最多执行一次。
